# Auto-Update Configuration

> LH-TV 2.x | Date: 2026-06-15 | RC3.1 Blocker #6 | Deployer Documentation

---

## Overview

LH-TV uses `electron-updater` for automatic updates. The update provider is configured at **runtime** via environment variables — no server URLs are hardcoded in the repository.

**If `UPDATE_SERVER_URL` is not set, auto-update is silently disabled.** The app functions normally without update checks.

---

## Quick Start

### Generic HTTP Server

```powershell
$env:UPDATE_SERVER_URL = "https://releases.example.com/updates/"
$env:UPDATE_PROVIDER = "generic"
.\LH.exe
```

### GitHub Releases (public repo)

```powershell
$env:UPDATE_SERVER_URL = "myorg/lh-tv-releases"
$env:UPDATE_PROVIDER = "github"
.\LH.exe
```

### GitHub Releases (private repo)

```powershell
$env:UPDATE_SERVER_URL = "myorg/lh-tv-releases"
$env:UPDATE_PROVIDER = "github"
$env:GITHUB_TOKEN = "ghp_xxxxxxxxxxxx"
.\LH.exe
```

### S3

```powershell
$env:UPDATE_SERVER_URL = "https://s3.amazonaws.com/my-bucket"
$env:UPDATE_PROVIDER = "s3"
$env:S3_BUCKET = "my-bucket"
$env:S3_REGION = "us-east-1"
$env:S3_PATH = "/updates/"
.\LH.exe
```

## Environment Variables

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `UPDATE_SERVER_URL` | **Yes** | — | Provider-specific URL (see below) |
| `UPDATE_PROVIDER` | No | `generic` | `generic`, `github`, or `s3` |
| `UPDATE_CHANNEL` | No | `latest` | Release channel: `stable`, `beta`, `rc` |
| `GITHUB_TOKEN` | For private repos | — | GitHub personal access token |
| `S3_BUCKET` | For S3 | — | S3 bucket name |
| `S3_REGION` | For S3 | `us-east-1` | AWS region |
| `S3_PATH` | For S3 | `/` | Path prefix in bucket |

## Provider Details

### generic (default)

Serves update manifests from any HTTP/HTTPS server.

**`UPDATE_SERVER_URL` format**: `https://your-server.com/path/to/updates/`

**Server requirements**:
- Serve `latest.yml` (auto-generated by `electron-builder --win`)
- Serve `.exe` installer files and `.exe.blockmap` files
- Support HTTP GET and HEAD requests
- Return correct `Content-Type` and `Content-Length` headers

**Example directory layout**:
```
updates/
  latest.yml
  LH Setup 2.0.0.exe
  LH Setup 2.0.0.exe.blockmap
  LH Setup 2.1.0.exe
  LH Setup 2.1.0.exe.blockmap
```

### github

Uses GitHub Releases API.

**`UPDATE_SERVER_URL` format**: `owner/repo` (e.g., `myorg/lh-tv-releases`)

**Setup**:
1. Create a GitHub repository for releases
2. Build the app with `npm run dist`
3. Upload `latest.yml`, `.exe`, and `.exe.blockmap` as release assets
4. For private repos, set `GITHUB_TOKEN` env var

### s3

Uses AWS S3 as the update server.

**`UPDATE_SERVER_URL` format**: S3 bucket URL

**Setup**:
1. Create an S3 bucket with public read access (or use signed URLs)
2. Upload build artifacts to the bucket
3. Configure `S3_BUCKET`, `S3_REGION`, `S3_PATH` as needed

## Release Channels

Use `UPDATE_CHANNEL` for staged rollouts:

```powershell
# Stable channel (default)
$env:UPDATE_CHANNEL = "stable"

# Beta channel
$env:UPDATE_CHANNEL = "beta"

# Release candidate channel
$env:UPDATE_CHANNEL = "rc"
```

With channels, the updater fetches `latest.yml` from `<UPDATE_SERVER_URL>/<channel>/`.

## Build Requirements

Auto-update requires **NSIS installer** builds. Portable builds do not support `electron-updater`.

### package.json configuration

```json
{
  "build": {
    "win": {
      "target": ["portable", "nsis"]
    },
    "nsis": {
      "oneClick": false,
      "perMachine": false,
      "allowToChangeInstallationDirectory": true,
      "createDesktopShortcut": true,
      "createStartMenuShortcut": true
    }
  }
}
```

Build command:
```bash
npm run dist
```

This produces:
- `dist/LH Setup X.Y.Z.exe` — NSIS installer (for auto-update)
- `dist/LH X.Y.Z.exe` — Portable executable (for manual distribution)
- `dist/latest.yml` — Update manifest

## Graceful Degradation

If `UPDATE_SERVER_URL` is not set:
- The updater service logs a warning: `UPDATE_SERVER_URL not set — auto-update disabled`
- No update checks are performed
- No errors are thrown
- The app runs normally

## Troubleshooting

| Symptom | Check |
|---------|-------|
| "Update check failed" | Verify `UPDATE_SERVER_URL` is accessible from the client machine |
| "New version not found" | Verify `latest.yml` lists a version > current app version |
| "Download failed" | Verify `.exe` and `.blockmap` files exist at the expected paths |
| GitHub 404 | Verify `UPDATE_SERVER_URL` format is `owner/repo` (no `https://` prefix) |
| GitHub 401 | Set `GITHUB_TOKEN` for private repos |
| S3 AccessDenied | Check bucket policy allows read access |

---

## Security Notes

- The update server should use HTTPS (required for `generic` provider URL validation)
- `latest.yml` contains SHA512 hashes — `electron-updater` verifies downloaded files
- `verifyUpdateCodeSignature: false` means code signing is not verified during updates — consider enabling for production
- `GITHUB_TOKEN` should be scoped to `repo` access only
