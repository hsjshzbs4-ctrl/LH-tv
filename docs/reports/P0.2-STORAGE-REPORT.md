## 四、Storage 变更详情

### 4.1 存储架构（重构前 vs 重构后）

**重构前**:
```
userStore (Pinia persist → localStorage key: lh-user-data)
     ↕ useStorageSync (双向桥接，10s 定时同步)
storage.service.ts (主进程 → user-data.json)

SearchView (localStorage key: lh_search_history) ← 独立，不互通
```

**重构后**:
```
                        ┌─ userStore ──────────┐
                        │  favorites           │
                        │  history             │
              ┌─────────┤  playbackPositions   ├─────────┐
              │         └──────────────────────┘         │
              │  getFavorites/setFavorites                │
              │  getHistory/setHistory                    │
              │  getPlaybackPositions/setPlaybackPositions│
              │  getSearchHistory/setSearchHistory        │
              ▼                                          ▼
     ┌────────────────────────────────────────────────────┐
     │              StorageService (单例)                  │
     │  内存缓存 → 防抖 500ms → IPC → 主进程文件            │
     └────────────────────────────────────────────────────┘
              │                                          │
              ▼                                          ▼
     userStore.loadFromStorage()              SearchView.saveHistory()
     (App.vue onMounted 触发)                 (即时持久化)
```

### 4.2 StorageService 接口

```typescript
class StorageService {
  // 核心
  load(): Promise<StorageSchema>
  save(data?: StorageSchema): Promise<boolean>
  saveNow(): Promise<boolean>          // 跳过敏抖，立即写入
  export(): Promise<string | null>
  import(json: string): Promise<ImportResult>

  // 类型访问器
  getFavorites(): Promise<FavoriteItem[]>
  setFavorites(items: FavoriteItem[]): Promise<void>
  getHistory(): Promise<HistoryItem[]>
  setHistory(items: HistoryItem[]): Promise<void>
  getPlaybackPositions(): Promise<Record<string, PlaybackPosition>>
  setPlaybackPositions(positions): Promise<void>
  getSearchHistory(): Promise<string[]>
  setSearchHistory(items: string[]): Promise<void>
  getSettings(): Promise<StorageSettings>
  setSettings(settings: StorageSettings): Promise<void>

  // 工具
  getStats(): Promise<StorageStats>
  invalidate(): void                   // 重置缓存，下次强制重新加载
  isLoaded: boolean
}
```

### 4.3 数据流优化

| 指标 | 重构前 | 重构后 |
|------|--------|--------|
| 数据持久化入口 | 3 个 (localStorage × 2 + IPC) | 1 个 (StorageService) |
| 同步延迟 | 10 秒定时 + localStorage 即时 | 500ms 防抖写入 |
| 搜索历史存储 | 独立 localStorage key | 统一到 user-data.json |
| 数据一致性 | ⚠️ 双轨可能不同步 | ✅ 单一数据源 |
| Pinia persist 依赖 | ✅ 需要 | ❌ 已移除 |

## 六、向后兼容

- **用户数据格式不变**: `user-data.json` 新增 `searchHistory` 字段，旧数据加载时自动补默认值
- **搜索历史迁移**: 首次加载时旧 `localStorage` 中的搜索历史不会自动迁移（简化设计），用户搜索历史将重新积累
- **收藏/历史/播放进度**: 主进程文件中的数据格式完全不变，无缝切换

## 七、风险评估

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 首次启动无搜索历史 | 🟢 低 | 预期行为；用户重新搜索后累积 |
| 防抖 500ms 可能丢失最后操作 | 🟢 低 | 应用退出前调用 `saveNow()` |
| 主进程 `storage.service.ts` 兼容旧数据 | 🟢 低 | 自动检测并补 `searchHistory: []` |
| `useStorageSync` 旧 API 引用 | 🟢 低 | 保留兼容导出，SettingsView 已迁移 |
