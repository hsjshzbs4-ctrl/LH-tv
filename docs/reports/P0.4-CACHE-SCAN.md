# LH-TV P0.4 Cache 架构扫描报告

> **日期**: 2026-06-12

## 1. Provider 调用统计

| API | 调用次数 | 位置 | 缓存现状 |
|-----|:---:|------|------|
| `getTypeCatalog` | 5 | HomeView×3, TVView, MoviesView | ❌ 无（每次直达 Provider） |
| `getAnimeCatalog` | 2 | HomeView, AnimeView | ❌ 无 |
| `getFullCatalog` | 1 | catalogStore | ⚠️ 内存 3h TTL |
| `getShowDetail` | 1 | PlayView | ❌ 无（每次切集重载） |
| `searchVideo` | 间接 | search-ipc.js | ⚠️ legacy CacheManager 1h |
| `getAnimeDetail` | 0(TS) | legacy only | ❌ 无 |

## 2. 重复请求分析

| 场景 | 触发次数/API | 可缓存? | 建议 TTL |
|------|:---:|:---:|:---:|
| 进入首页 | 4 次 (tv/movie-cn/movie-us/anime) | ✅ catalog | 1h |
| 首页海报更新事件 | 重新触发 4 次 | ✅ catalog | 1h |
| 切换分类标签 | 1 次/tag | ✅ catalog | 1h |
| 进入播放页 | 1 次 detail | ✅ detail | 6h |
| 切集 | 1 次 play source reload | ✅ episode | 6h |
| 搜索相同关键词 | 1 次/搜索 | ✅ search | 30min |
| 返回首页 (keepAlive) | 0 (缓存有效) | — | — |

## 3. 现有缓存设施

| 模块 | 位置 | 类型 | TTL | 限制 |
|------|------|------|-----|------|
| `CacheManager` (legacy) | `shared-legacy/cache-manager.js` | 内存 LRU | 通用 1h | maxSize=200 |
| `searchCache` | `show-catalog.js:25` | 内存 LRU | 1h | maxSize=100 |
| `catalogStore` | `src/stores/catalog.ts` | 内存 ref | 3h | 仅全量目录 |
| `posterCache` | `poster-fetcher.js` | 磁盘 JSON | 无 TTL | 文件 `_poster_cache.json` |

## 4. 海报系统

- 海报缓存：`userData/posters/` 目录 + `_poster_cache.json` 索引
- 格式：混合 `file:///` 本地路径 + 远程 URL
- 增量刷新：只补缺失的（检查 `getCachedPoster` 是否返回 `file://` 开头）
- 强制全量：清空缓存文件后重新抓取

## 5. 当前问题

1. **无跨组件缓存**：HomeView/TVView/MoviesView 各自发起相同 API 调用
2. **catalogStore 只缓存全量目录**：`getTypeCatalog('tv','cn')` 不走缓存，每次都到 Provider
3. **legacy CacheManager 未 TS 化**：旧 JS 模块，无类型安全
4. **无磁盘持久化缓存**：应用重启后所有 catalog/detail 缓存失效
5. **海报无 TTL**：旧海报永不过期，需手动强制刷新
