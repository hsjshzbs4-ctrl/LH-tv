## 七、新增泛型 `invoke<T>()`

`preload.ts` 新增类型安全调用方法：

```typescript
// 用法示例
const result = await window.app.invoke<IpcChannelMap['get-home-data']>('get-home-data')
// result 类型自动推导为 HomeData
```

现有 `window.app.getHomeData()` 等方法保持不变，向后完全兼容。

## 八、风险评估

| 风险 | 等级 | 状态 |
|------|------|------|
| IPC 枚举值 ≠ 旧字符串导致运行时错误 | 🟢 低 | ✅ 一一对应，已验证 |
| 类型收缩后 API 实际返回不匹配 | 🟡 中 | ⚠️ 旧 JS 模块不受 TS 约束，运行时可能返回多余字段或缺少字段。已在 `catalogStore` 中添加 defensive `flattenCatalogMap` 处理 |
| 旧 `shared-legacy/` 模块 import 不受影响 | 🟢 低 | ✅ 旧 JS 文件仍用原始字符串，不受枚举影响 |
| `@shared` alias 在 electron-vite 打包后路径解析 | 🟢 低 | ✅ 已添加 alias 到 `electron.vite.config.ts` 和 `tsconfig.json` |
| 向后兼容旧 import `@/types` | 🟢 低 | ✅ `src/types/index.ts` 保持 re-export 全部类型名 |

## 九、后续建议

1. **P0.2 — 统一 Storage**：将 `userStore` 的 Pinia persist 从 `localStorage` 迁移到 `StorageService`，消除双轨存储
2. **P0.3 — CacheManager**：用 TS 重写旧 `cache-manager.js`，按 TTL 分层 (poster/detail/play/search)
3. **P0.4 — HLS Player**：`PlayView.vue` 接入 `PlayerEngine + HLSAdapter`，封装 `hls.js`
4. **旧 IPC 模块迁移**：`shared-legacy/ipc/*.js` 中的 IPC handler string 后续逐步迁移到枚举
5. **`as Video[]` 消除**：7 个 view 文件中仍有 `as Video[]` 断言，需在每个 view 中做类型守卫或 map 转换
